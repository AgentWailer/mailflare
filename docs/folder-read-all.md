# Actions on an entire folder

The header checkbox selects the visible page. **Select entire folder** (or **Select all matches** with a filter) extends the selection across every page. A read-only preparation request obtains the exact message count, unread count, accessible mailboxes and row-ID boundary. The banner then shows **All N selected**; existing toolbar actions act on this selection. Clearing selection or changing folder, mailbox, search/filter or page returns to page selection. Unchecking a row also returns to page selection.

Archive, move to Trash, spam/not-spam, read/unread, restore and folder moves use the existing bulk action service. Labels and categories use the existing organization service, including confirmed category learning and preserved unrelated labels. For a global label change, choose **Add labels to all** or **Remove labels from all** explicitly. Labels and folder moves require a single mailbox. Read-only shared grants permit read/unread changes; management actions require management rights for the entire selection. Access is checked on every chunk and changing login sessions cancels the task.

Moving an entire selection to Trash asks for confirmation and retains message objects. Permanent deletion is offered only in Trash/Spam, asks for the existing irreversible-delete confirmation, and deletes raw MIME/attachment objects through the existing cleanup service. Simply extending the selection never changes or deletes mail. Mail received or imported after the selection boundary stays outside the operation.

Processing uses bounded requests to `/api/messages/bulk-scope`: 80 messages for simple updates, 5 for permanent deletion or label/category changes, and individual messages for expensive spam feedback. A row-ID cursor scans forward without repeatedly sorting the remaining archive. No complete archive or archive-wide ID list is downloaded. Progress is shared across folder pages; counters, cached details and other tabs reconcile periodically and at completion/error. The old `/api/messages/read-all` remains compatible with already-open older app versions.

Keep the app open until completion. These are browser-managed operations, not persistent queue jobs: closing/reloading stops further chunks. Completed chunks remain saved. An interrupted request offers **Continue** with the same scope, action and checkpoint. Retrying does not include subsequently received mail.

Pull to refresh uses native touch listeners at the top of the mobile list. Its isolated wrapper animates via transforms so the mail rows do not rerender for every move. Increasing drag resistance, a short minimum refresh display and eased return keep quick responses smooth. Short pulls, horizontal row swipes, normal scrolling, multitouch and controls do not trigger refresh. Reduced-motion preferences disable the return animation.
