# Email assistant and MCP

Configure the AI provider in **Admin → Agent**. Mailflare supports Cloudflare Workers AI and OpenAI-compatible providers. You can configure multiple models, then choose a model for each mailbox in the assistant's **Settings** view. Assistant chat is available by default once a provider is configured; an admin can turn it off in **Admin → Agent**. The assistant works within the selected mailbox. Mailbox managers can set writing instructions, a draft reviewer, and a daily auto-draft limit. Automatic reply drafts are off until enabled for that mailbox, and a person must review a draft before sending it. **Admin → Agent → View Usage** shows AI request totals, estimated spend, daily usage, and a paginated activity log.

You can follow up on an assistant draft in chat. The assistant can revise its body, subject, sender, recipients, and send time, copy an attachment from an email in the selected mailbox, or remove a draft attachment. It reads the latest draft revision before editing. A requested send time does not queue delivery on its own: the assistant creates a review link, and the user confirms the exact draft and time in Mailflare. The composer can also edit an assistant draft, add local files, and request the same review. Apply the latest database migration before using scheduled assistant drafts.

While the assistant is responding, you can enter more messages. They appear in a queue above the prompt and run in order after the current response. You can edit or remove a queued message, or choose **Steer** to stop the current response and send that queued message next. Switching chats or closing the assistant clears the local queue.

For ChatGPT's native MCP app connection, use [Cloudflare Managed OAuth](mcp-cloudflare-oauth.md). In **Settings → API keys**, enable the OAuth grant for your verified Cloudflare login and choose the personal MCP key defining its permissions. Add the displayed MCP URL through ChatGPT's app settings using OAuth. No fixed key or Cloudflare service headers are entered in ChatGPT for this flow. Mail sending still requires confirmation in Mailflare.

To connect an external AI client, create a key in **Settings → API keys** and enable **Allow MCP access**. Choose the permitted mailboxes and mail tools. After creation, copy the key into your client’s secure authentication field; the key is shown only once. Copyable agent instructions contain no secret and do not register a connection by themselves. Connect the client to `https://<your-mailflare-origin>/mcp` using Streamable HTTP and `Authorization: Bearer <key>`. Mail MCP access is limited to the selected mailboxes and the key owner's current permissions. An alias shares its parent mailbox, so selecting that mailbox also includes mail delivered to its aliases. The MCP `request_send` tool creates a review request; sending still requires confirmation in Mailflare. MCP mail tools do not require an AI provider.

MCP clients can use `update_draft` for the same draft fields and attachments, then `request_send` to create a human review for immediate or scheduled delivery. Attachment additions copy an existing file from an email in the key's permitted mailbox; local files are added through the composer.

Calendar access uses separate **Read calendar** and **Manage calendar** MCP permissions. The personal calendar exposes `get_calendars`, `get_schedule`, `search_events`, `get_event`, `find_free_time`, `create_event`, `update_events`, and `delete_events`. Calendar-only keys need no mailbox selection. Calendar writes save immediately. Event updates and deletes use series IDs and affect the entire recurring series; these tools record attendees but do not send invitations or cancellations. Supply absolute ISO 8601 times with offsets. Schedule and availability ranges are limited to 90 days.

For management tools, create a separate MCP key in **Admin → API keys**. Its selected domain, account, and mailbox management permissions do not grant access to mail content. This page also provides copyable AI agent instructions after key creation.


## Refine email text

The sparkle button immediately to the left of **Send** starts Refine using the last style and language selected on this device. Select a passage first to refine it, or leave the selection empty to refine the editable email body. The suggestion appears in the original editor area with a brief blue highlight. **Replace** accepts it, **Try again** generates another suggestion from the original text, and **Cancel** restores the original view. Until accepted, suggestions do not change the draft and sending is disabled. The settings icon opens compact style and language controls; changing an option immediately regenerates the proposal. Available styles are Polish, More professional, Friendlier, Shorter and More detailed, with original language, German or English. The toolbar's **Undo refinement** action restores the original content until you edit it again.

If the editable body is empty (including signature-only replies), the same button proposes a new reply using the complete conversation in chronological order. Style and language preferences also apply to these proposals; keeping the language uses the latest relevant email. The server reads the stored thread with source-mailbox access checked separately from permission to send in the selected mailbox. Unsent drafts are excluded. Imported or forwarded messages without stored thread identifiers can use the quoted history. Without a conversation, the composer asks the user to open a reply or write some text. The full history is limited to 60,000 characters including headers; larger conversations are rejected rather than silently shortened. Changing recipients, subject or conversation while generating a reply discards the proposal.

On phones the floating composer fills the visual viewport, including adjustments when the software keyboard opens. Send, Refine and attachments remain in the bottom toolbar; formatting controls expand on demand.

Refine uses the AI provider configured under **Admin → Assistant** and the mailbox's selected model. It respects the administrator's assistant-enabled setting, session origin rules, the existing per-user AI rate limit and permission to send on behalf of the selected mailbox. A read-only mailbox grant is insufficient. Usage is recorded with source `refine`. No new schema migration or provider credential is required.

For existing-text refinement, only the selected passage or editable message body is sent to the AI provider. Empty-body reply proposals send the conversation and composing headers to the configured provider. The signature and folded quoted conversation are preserved; inline images are represented by protected placeholders and restored locally. The generated prose uses plain text and line breaks; existing rich formatting inside the rewritten passage is simplified, while surrounding content remains intact. A suggestion cannot overwrite content or a sending-mailbox change made while it is being generated. Refine does not send mail or change draft records on the server; applying the result participates in the composer's usual draft autosave.

Requests accept up to 12,000 characters, and incomplete or invalid model output is rejected. The feature's controls and messages are available in German and English; other interface locales use the English fallback. AI processing uses your configured provider and its usual usage charges.
